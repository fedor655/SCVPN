# SCVPN для macOS

Нативный клиент: SwiftUI-приложение и привилегированный демон, оба на Swift, без
единой внешней зависимости. Собранный бандл — 2,6 МБ.

## Сборка и запуск

```bash
./build.sh && open dist/SCVPN.app
```

`swift run` для приложения **не работает и не должен**: SwiftUI из SPM-таргета
обязан запускаться из собранного бандла, иначе `Bundle.main` укажет на `.build`,
не подхватится `Info.plist` с `NSCameraUsageDescription`, и приложение получит
не ту activation policy. Для демона и проверок `swift build` / `swift test`
работают как обычно.

Требуется Apple Silicon: сборка на Intel обрывается с ошибкой. Минимальная
система — macOS 13.0.

## Интерфейс

Экран — кнопка подключения, статус и список серверов. Всё остальное в меню «⋯»:

| Пункт | Что делает |
|---|---|
| Способ подключения | системный прокси или TUN (весь трафик, нужен root) |
| Отпечаток TLS | авто-подбор или конкретный |
| Сетевой стек TUN | gvisor / system / mixed — крутить, если туннель странно себя ведёт |
| Включать системный прокси | только для режима «прокси» |
| Блокировать рекламу | правило в конфиге Xray |
| Раздельное туннелирование… | маршрутизация целиком: всё через VPN, обход, или какие приложения идут в туннель (нужен TUN) |
| Подписки… | список подписок, ссылка, QR-код, удаление подписки целиком |
| Измерить пинг | TCP-пинг всех серверов |
| Скачать ядро Xray | разовая загрузка ядра и гео-баз |
| Скачать компоненты TUN | попросить системный компонент скачать `sing-box` |
| Удалить компоненты TUN… | виден, только когда есть что удалять |
| Удалить системный компонент… | снять привилегированный демон |
| Показывать лог ядра | панель с выводом Xray внизу окна |

Полосы заголовка у окна нет: содержимое заведено под неё, светофор опущен в
центр шапки, окно тащится за шапку.

### Раздельное туннелирование по приложениям

Работает — проверено живьём: исключённый процесс уходит мимо туннеля,
неисключённый остаётся в нём.

**Браузеры на WebKit выбирать бесполезно.** Safari сам в сеть не ходит: за него
это делает отдельный процесс `com.apple.WebKit.Networking`. Правило по имени
«Safari» не совпадёт ни с одним запросом, и выглядит это как сломанный
раздельный туннель. Выбирать надо `com.apple.WebKit.Networking` — в диалоге об
этом написано.

## Как устроен TUN и почему так

TUN на macOS требует root. Можно было бы спрашивать пароль на каждое
подключение, но тогда остаётся дыра, из-за которой такие клиенты и славятся
нестабильностью: приложение упало или его сняли, а `sing-box` работает от root
и держит маршруты. Весь трафик системы уходит в мёртвый туннель, и выглядит это
как «интернет пропал». Прибить `sing-box` может только root, то есть нужен ещё
один диалог пароля — а показать его уже некому.

Поэтому приложение держит открытое соединение с демоном всё время работы.
Оборвалось соединение — значит приложение мертво — демон сам сносит `sing-box`
и возвращает маршруты. Не при следующем запуске, а сразу.

### Как ставится системный компонент

Через `SMAppService`: plist едет внутри бандла, в
`Contents/Library/LaunchDaemons/com.scvpn.helper.plist`. Отдельного файла в
`/Library/LaunchDaemons/` не создаётся, копировать код демона никуда не надо.

**Первый `register()` штатно возвращает ошибку** `code=1` и переводит службу в
`requiresApproval`. Это не сбой, а шаг сценария: система plist приняла, ей нужно
согласие пользователя в System Settings → General → Login Items. Снять компонент
вручную — там же.

**Подмена бандла на месте службу не обновляет.** Проверено: ни новый бинарник,
ни изменённый plist не подхватываются, а служба перестаёт подниматься вовсе.
Поэтому приложение хранит `helper_version` в `settings.json` и при несовпадении
делает `unregister()` + `register()`. Это условие корректности, а не
оптимизация: `ExitTimeOut = 40` — расчёт худшего случая снятия, и служба со
старым значением получит SIGKILL на середине снятия.

**Ограничения по расположению бандла нет.** Проверено живьём из `/Applications`,
`~/Applications`, `/Users/Shared` и `~/Downloads` — везде регистрация проходит и
демон поднимается от root.

## Структура

| Файл | За что отвечает |
|------|-----------------|
| `../../core-swift/Sources/SCVPNCore/` | вся логика: модели, парсеры, конфиги, хранилище, клиент демона. Отдельный пакет: тот же код линкуется в iOS-приложение |
| `core-swift/…/SCVPNCore/SingboxConfig/` | конфиг sing-box и валидация недоверенного ввода |
| `core-swift/…/SCVPNCore/HelperClient.swift`, `Tun.swift` | клиент демона: поднять и снять туннель |
| `core-swift/…/SCVPNCore/SystemProxy.swift` | системный прокси через `networksetup`, со снимком для отката |
| `core-swift/…/SCVPNCore/HelperInstaller.swift` | регистрация демона через `SMAppService` |
| `Sources/SCVPNHelperKit/` | логика демона: сокет, надзор за sing-box, установка sing-box |
| `Sources/SCVPNHelper/main.swift` | точка входа демона, десяток строк |
| `Sources/SCVPNApp/` | SwiftUI: окно, меню, диалоги |
| `Tools/smprobe/` | зонд `SMAppService`: проверить поведение службы вне приложения |

Логика демона живёт в `SCVPNHelperKit`, а не в исполняемом таргете, потому что
SwiftPM не даёт тестовому таргету линковать executable. Ровно по той же причине
платформенный слой приложения лежит в `SCVPNCore`, а не в `SCVPNApp`.

`SCVPNCore` — отдельный SwiftPM-пакет в корне репозитория (`core-swift/`), а не
таргет этого пакета: его же линкует iOS-версия. Платформенное внутри разделено
`#if os(macOS)` / `#if os(iOS)`.

## Проверка

```bash
swift test                          # всё
swift test --filter DeadMansSwitch  # одна группа
```

Три проверки трогают систему по-настоящему, и это осознанно:

- `SystemProxyLiveTests` включает и выключает системный прокси на этой машине —
  молча сломанный откат оставляет без интернета, и ловить это надо здесь.
  Пропускается, если на машине уже стоит **чужой** прокси: падение посреди
  проверки затёрло бы его настройку.
- `SignalTests` поднимает демона отдельным процессом и шлёт ему сигналы.
- `RealProfilesTests` читает настоящий `profiles.json` из
  `~/Library/Application Support/SCVPN/`, если он есть, и прогоняет через круг
  чтение-запись: формат на диске заморожен, и потерянное поле — потерянная
  подписка. Файла нет — `XCTSkip`, а не зелёный молчком.

### Ручная проверка TUN и dead-man's switch

Отдельная машина, где потерять сеть на пару минут не страшно, и **не по
SSH-сессии в неё же**: провальный исход означает трафик, запертый в мёртвом
туннеле, а приложение, которое могло бы его снять, уже убито.

1. Режим «прокси»: подключиться, проверить `networksetup -getwebproxy Wi-Fi`
   (`Enabled: Yes`, `Server: 127.0.0.1`), отключиться, проверить `Enabled: No`.
   Браузером, не `curl`: консольные утилиты про эту настройку не знают.
2. Переключиться на TUN в том же окне, подключиться.
3. Убедиться, что туннель поднят: `pgrep -f "sing-box run -c"` непусто и
   `curl -s https://api.ipify.org` показывает адрес сервера. Наличие `utun` само
   по себе не доказательство — посторонних `utun0..utun9` на машине хватает.
4. **Главное.** При поднятом туннеле убить приложение `kill -9` и убедиться, что
   **PID демона остался тем же**, а `sing-box` исчез. Сменился PID — значит демон
   тоже погиб, его поднял launchd, а новый подметает сироту сам, и проверка
   позеленеет при полностью сломанном обнаружении обрыва.
5. Раздельное туннелирование: исключить процесс, который ходит в сеть сам
   (`curl` годится, Safari — нет, см. выше), и сверить его выход с выходом
   неисключённого.

## Общий код с Windows

Общего кода нет. `../Windows/shared/` — парсеры ссылок и подписок, модели,
конфиг Xray, хранилище — это код Windows-версии на Python, и лежит он внутри
Windows-папки, потому что больше нигде не используется. macOS и iOS свою половину имеют отдельно, в
`core-swift/Sources/SCVPNCore/`, и **каждая правка логики делается дважды**:
один раз в Python для Windows, один раз в Swift для обеих Apple-платформ. Иначе
реализации разойдутся молча, и заметит это пользователь.

Форматы, которые обязаны совпадать побайтно — их расхождение не «разные
реализации», а испорченные данные:

- `profiles.json` — имена ключей `Server`, включая `protocol`, `alter_id`,
  `public_key`, `short_id`, `spider_x`, `allow_insecure`, `ws_path`, `ws_host`,
  `grpc_service`;
- `settings.json` — имена и умолчания, включая `hwid` и неизвестные ключи,
  которые обязаны переживать круг чтение-запись;
- `Server.key()` — формат `протокол://секрет@адрес:порт/сеть/безопасность`, он
  лежит в `settings.json` как `selected_key`;
- HWID — соль `scvpn-hwid-v1` и формат UUID из хеша: смена любого означает новый
  слот в лимите устройств у каждого пользователя;
- протокол сокета демона целиком;
- палитра — она же в `android/app/src/main/res/values/colors.xml`, и её сверяет
  `test_palette_matches_android_colors_xml`.
