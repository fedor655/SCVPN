# scvpn-awg — AmneziaWG для SCVPN

Маленький бинарник, который отдаёт туннель AmneziaWG локальным SOCKS5 на
`127.0.0.1`. Общее описание проекта — в [README репозитория](../README.md).

## Зачем он вообще нужен

Ядро Xray умеет `wireguard`, но **не умеет обфускацию Amnezia** — `Jc`,
`S1…S4`, `H1…H4`. Проверяется одной командой:

```bash
strings ~/Library/Application\ Support/SCVPN/bin/xray | grep -ci amnezia
```

Ноль. У sing-box то же самое: [PR #2670](https://github.com/SagerNet/sing-box/pull/2670)
не влит. А `H1…H4` подменяют тип сообщения WireGuard, поэтому **обычный
WireGuard-клиент к такому серверу не подключится вовсе** — не «медленнее», а
никак, без единой строки в логе. Это худший вид отказа, и полагаться на
«авось это обычный WG» нельзя.

Значит нужен код, который это умеет. Взят официальный
[amnezia-vpn/amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go),
закреплённый в [go.mod](go.mod) конкретной версией. Здесь к нему добавлены
только разбор `.conf`, строка UAPI и SOCKS5 — три файла, которые видно
целиком.

## Почему SOCKS, а не свой TUN

Приложение уже умеет заводить системный трафик в локальный SOCKS: этим
занимаются системный прокси, sing-box на десктопе и hev-socks5-tunnel на
Android. Если отдать AmneziaWG тем же интерфейсом, то маршруты, DNS,
killswitch и раздельное туннелирование **писать заново не нужно** — они уже
есть и работают. TCP/IP-стек живёт внутри процесса (gvisor netstack из
amneziawg-go), наружу торчит только `127.0.0.1`.

```
трафик → инбаунды Xray → outbound socks → scvpn-awg → AmneziaWG → сервер
```

Xray остаётся впереди и продолжает делать то, что делал: geosite, обход РФ,
блокировку рекламы, DNS. Разница ровно в одном outbound.

Побочный выигрыш: на Windows появляется WireGuard **без прав администратора** —
режим системного прокси работает, потому что TUN-адаптер никто не создаёт.

## Что он делает

```
scvpn-awg -config <путь.conf> -socks 127.0.0.1:10810
scvpn-awg -config <путь.conf> -probe https://www.gstatic.com/generate_204
```

* `-config` — `.conf` формата wg-quick плюс поля AmneziaWG. Тот самый файл, что
  даёт панель, и тот самый текст, что лежит в QR-коде.
* `-socks` — где слушать. При готовности печатает
  `[awg] готов: SOCKS5 на <адрес>, пир <endpoint>`; **эту строку ждут
  супервизоры на всех платформах**, менять её только вместе с ними.
* `-probe` — поднять туннель, померить задержку запросом сквозь него, напечатать
  миллисекунды и выйти. Так меряется пинг WG-сервера: TCP-коннектом Endpoint не
  измерить, WireGuard живёт на UDP.

SOCKS5 поддерживает CONNECT и UDP ASSOCIATE. UDP здесь обязателен, а не «на
будущее»: без него отваливается QUIC, то есть треть веба.

## Сборка

Нужен Go (версия — в [go.mod](go.mod)).

```bash
./build.sh          # в dist/
go test ./...       # разбор .conf и строка UAPI
```

`CGO_ENABLED=0`, поэтому кросс-компиляция идёт с любой машины. Исключение —
32-битные ABI Android и `android/amd64`: их Go собирает только внешним
линковщиком. Если нужен эмулятор или устройство старше 2016 года, поставь NDK и
задай `ANDROID_NDK_HOME` — скрипт подхватит его сам, а без него честно скажет,
что пропустил.

Куда класть готовое, печатает сам скрипт.

## Про версии AmneziaWG

`amneziawg-go` на master — это AWG 3.1, а живые серверы Amnezia сплошь и рядом
1.5. Имена параметров совместимы снизу вверх, но совместимость **на проводе**
между клиентом 3.x и сервером 1.5 гарантией не является. Поэтому версия в
`go.mod` закреплена, а не берётся с master: обновлять её нужно осознанно и с
проверкой на живом сервере.

Список параметров обфускации намеренно открытый (см. `awgParams` в
[conf.go](conf.go)): Amnezia добавляет их от версии к версии, имена берутся из
`.conf` как есть и уезжают в UAPI как есть. Ядро само скажет, если ключ ему
незнаком.
