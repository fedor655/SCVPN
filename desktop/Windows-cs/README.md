# SCVPN для Windows

Клиент-обёртка вокруг открытого ядра [Xray-core](https://github.com/XTLS/Xray-core).
Общее описание проекта и разбор архитектуры — в [README репозитория](../../README.md).

Приложение нативное: C# и WPF, .NET 10. Собирается под x64 и arm64 —
Windows on ARM поддерживается без оговорок.

## Что нужно поставить

* [.NET 10 SDK](https://dotnet.microsoft.com/download) — обязательно;
* Visual Studio 2022/2026 с рабочей нагрузкой «.NET desktop development»
  либо JetBrains Rider — по желанию, собрать можно и одним `dotnet`;
* [Inno Setup 6.3](https://jrsoftware.org/isdl.php) или новее — только для
  сборки установщика (идентификатор `x64compatible` появился в 6.3).

## Запуск из исходников

```powershell
dotnet run --project SCVPN
```

При первом запуске: меню **«⋯» → «Скачать ядро Xray»**, затем кнопка **+** —
вставь `vless://…` ссылку или URL подписки, выбери сервер и жми большую кнопку.

## Тесты

```powershell
dotnet test
```

Проверяются места, где ошибка тихая: разбор ссылок, сборка конфигов Xray и
sing-box, чтение и запись профилей и настроек, HWID, выбор бинарников по
архитектуре, сверка палитры с Android-версией.

Эталоны в `SCVPN.Tests/Golden/` сняты с двух работающих реализаций — прежней
на Python и `core-swift`. Что откуда взято и три осознанных расхождения с
Python — в `SCVPN.Tests/Golden/README.md`.

Сквозная проверка на живой машине (замена `smoke_test.py`) в обычный прогон не
попадает: она поднимает ядро, ходит в сеть и читает настоящие профили.
Отдельно:

```powershell
$env:SCVPN_LIVE=1; dotnet test --filter Category=Live
```

## Сборка

```powershell
.\build.ps1                 # обе архитектуры, приложение и установщик
.\build.ps1 -Arch arm64     # только arm64
.\build.ps1 -NoInstaller    # без установщика
```

Версия задаётся в одном месте — `Directory.Build.props`; `build.ps1` читает её
оттуда и передаёт в Inno Setup.

Кросс-сборка работает в обе стороны: с arm64-машины собирается x64 и наоборот.
Если `ReadyToRun` для чужой архитектуры откажется работать, помогает
`-NoR2R` — потеряется только скорость холодного старта.

## Структура

| Папка | За что отвечает |
|---|---|
| `SCVPN/Core/` | логика: модель сервера, разбор ссылок и подписок, конфиги Xray и sing-box, хранилище, запуск ядра, подбор отпечатка. Про WPF не знает |
| `SCVPN/Native/` | Windows: пути, реестр, системный прокси, HWID, список процессов, права администратора, загрузчик ядер, TUN |
| `SCVPN/Theme/` | палитра, метрики, стили |
| `SCVPN/Controls/` | самодельные элементы: кнопка питания, знак, панель лога |
| `SCVPN/Views/` | окна |
| `SCVPN.Tests/` | тесты и эталонные файлы |
| `setup/` | установщик Inno Setup |

## Режимы

- ✅ **Системный прокси** — без прав админа, покрывает браузеры и большинство
  приложений.
- ✅ **TUN — весь трафик**: Xray делает соединение с сервером, а `sing-box`
  заворачивает в него весь трафик системы через виртуальный адаптер. Требует
  прав администратора (приложение само предложит перезапуститься).

## Где лежат данные

`%LOCALAPPDATA%\SCVPN`:

- `profiles.json` — подписки и серверы;
- `settings.json` — настройки;
- `xray_running.json` / `singbox_running.json` — конфиги, реально отданные ядрам;
- `logs/` — лог аварий.

Чтобы данные легли в другое место (удобно при отладке), задай переменную
окружения `SCVPN_DATA_DIR`.

Папка `bin/` рядом с приложением — ядра и гео-базы. В git не попадает и в
установщик не кладётся: бинарники зависят от архитектуры, приложение
скачивает их само. Метка `bin/arch.txt` помнит, под какую архитектуру они
скачаны, и при несовпадении приложение предложит скачать заново.
